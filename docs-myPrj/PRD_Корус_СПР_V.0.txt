PRD: Корус СПР — Система принятия решений по крупным сделкам

Статус: Draft
Приоритет: High
Дата: 2026-03-16

Цель

Разработать веб-систему для организации многосторонних согласований
крупных сделок с контролем доступа по ролям, уведомлениями по email,
полным логированием действий и фиксацией итоговых решений.

Пользователь

Корпоративные сотрудники компании: администраторы бизнес-процесса,
инициаторы сделок, согласующие (постоянные и приглашаемые), наблюдатели.

User Story

Как инициатор, я хочу запустить процесс согласования сделки, чтобы
получить структурированное решение от группы согласующих с фиксацией
всех мнений и итогового результата.

Роли системы

1. Администратор (администратор бизнес-процесса)

-   Создаёт учётные записи пользователей

-   Создаёт сделки и задаёт их атрибуты

-   Назначает инициатора на сделку; может заменить инициатора на
    незакрытой сделке

-   Добавляет наблюдателей по запросу инициатора

-   Добавляет и изменяет состав согласующих (постоянных + приглашаемых)

-   Изменяет крайний срок согласования

-   Получает уведомление при завершении голосования (истёк срок или все
    проголосовали)

-   Экспертно проставляет итоговый статус сделки (может сделать до
    истечения срока голосования)

2. Постоянная группа согласующих

-   Пул пользователей, идентифицируемых по email

-   Изменения состава группы применяются к предстоящим (не запущенным)
    процедурам

-   Не затрагивают текущие (запущенные) и завершённые процедуры

3. Приглашаемые согласующие

-   Добавляются администратором к конкретной сделке дополнительно к
    постоянной группе

4. Инициатор

-   Видит только сделки, на которых у него статус «инициатор»

-   Наполняет сделку документами, заполняет форму карточки сделки

-   Запускает процесс согласования

-   Может отозвать сделку (с обязательным комментарием)

-   Может повторно отправить ссылку на сделку конкретному участнику из
    числа работающих с ней лиц

5. Наблюдатель

-   Доступ предоставляется администратором по запросу инициатора

-   Видит сделку и документы; не участвует в голосовании

-   Получает уведомление с итоговым статусом по email

Атрибуты сделки

  Поле            Тип        Описание
  --------------- ---------- -----------------------------------------------------------
  Клиент          text       Наименование клиента
  Подразделение   text       Инициирующее подразделение
  Предмет         text       Предмет сделки
  Сумма всего     number     Общая сумма сделки
  Крайний срок    datetime   Дата и время завершения согласования
  Статус          enum       Draft / Active / Closed / Approved / Rejected / Withdrawn

Процесс согласования

Этап 1: Подготовка сделки

1.  Администратор создаёт сделку (атрибуты + назначение инициатора)

2.  Администратор добавляет согласующих (из постоянной группы + при
    необходимости приглашаемых)

3.  Инициатор загружает документы и заполняет карточку сделки

Этап 2: Запуск согласования

1.  Инициатор нажимает «Запустить согласование»

2.  Все согласующие получают email со ссылкой на сделку

3.  Статус сделки переходит в Active

Этап 3: Голосование

1.  Согласующий просматривает документы — каждое обращение логируется
    (user, document, timestamp, action)

2.  Оставляет комментарии к документам; все комментарии по сделке можно
    просмотреть разом

3.  Принимает решение: Согласовать / Не согласовать

    -   Согласовать: можно прямо из email (magic link) или в системе

    -   Не согласовать: только в системе, комментарий обязателен

4.  К любому решению можно добавить или изменить оговорку (текст) —
    сразу или позднее

5.  Все решения видны всем согласующим

6.  Решение нельзя отозвать — только дополнить оговоркой

Этап 4: Завершение

Триггеры завершения (любой из двух):

-   Наступление крайнего срока

-   Все назначенные согласующие проголосовали

Действия:

1.  Администратор получает уведомление

2.  Администратор проставляет итоговый статус (может сделать и до
    наступления триггера)

3.  Итоговый статус рассылается по email всем участникам и наблюдателям

4.  Статус сделки переходит в Closed (Approved / Rejected / Withdrawn)

Варианты закрытия:

-   Approved / Rejected — по результатам голосования (решение
    администратора)

-   Withdrawn — отзыв инициатором или решением руководителя (обязателен
    комментарий)

После закрытия

-   Все изменения содержания сделки заблокированы

-   Добавление комментариев заблокировано

-   Голосование прекращено

-   Сделка, документы, комментарии доступны для просмотра всем
    согласующим

-   Общий список всех (включая закрытые) сделок и документов доступен
    всем согласующим

Функциональные блоки

F1: Управление пользователями

-   Создание учётных записей (только администратор)

-   Управление постоянной группой согласующих

-   Назначение ролей на сделку: инициатор, согласующий, наблюдатель

F2: Управление сделками

-   CRUD атрибутов сделки (только администратор)

-   Назначение / смена инициатора (только незакрытые сделки)

-   Назначение / изменение состава согласующих

-   Изменение крайнего срока

F3: Документы сделки

-   Загрузка документов инициатором

-   Просмотр документов всеми участниками и наблюдателями

-   Полный лог обращений: user_id, document_id, timestamp, action (view
    / download)

F4: Процесс согласования

-   Запуск процесса (инициатор)

-   Email-уведомления с magic link для быстрого согласования из письма

-   Голосование: approve / reject + опциональный комментарий

-   Оговорка к решению (добавить / изменить текст)

-   Повторная отправка ссылки конкретному участнику (инициатор)

F5: Комментарии

-   Комментарии к отдельным документам

-   Сводный просмотр всех комментариев по сделке на одном экране

F6: Завершение и уведомления

-   Триггер завершения по таймеру или полному голосованию

-   Уведомление администратора

-   Простановка итогового статуса администратором

-   Закрытие сделки (Withdrawn) с обязательным комментарием

-   Email-рассылка итогового статуса всем участникам и наблюдателям

F7: Журнал (Аудит)

-   Лог обращений к документам

-   Лог изменений атрибутов сделки

-   Лог голосований и изменений оговорок

Acceptance Criteria

-   Администратор может создать учётную запись, сделку и назначить на
    неё инициатора

-   Инициатор видит только сделки со своим статусом, загружает документы
    и заполняет карточку

-   При запуске согласования все согласующие получают email со ссылкой

-   Положительное решение можно принять прямо из email (magic link)

-   Отказ в согласовании возможен только в системе и только с непустым
    комментарием

-   Все обращения к документам логируются (кто, когда, какой документ,
    действие)

-   Каждый согласующий видит решения остальных согласующих

-   К решению можно добавить оговорку (текст), но отозвать решение
    нельзя

-   Инициатор может повторно отправить ссылку конкретному участнику

-   Закрытие сделки блокирует все изменения, но сохраняет полный доступ
    для просмотра

-   Итоговый статус рассылается по email всем участникам и наблюдателям

-   Общий список всех сделок и документов доступен всем согласующим
    после закрытия
